feat(scanner)!: checkpoint the Path Header Scanner 1.0 foundation

Checkpoint the first production foundation for Path Header Scanner. This
prepares the project's first formal SemVer release baseline and consolidates
the complete scanner, configuration, safety, architecture, testing,
documentation, container, automation, and developer-workflow foundation rather
than describing an upgrade from an earlier published version.

Path Header Scanner provides a preview-first workflow for discovering supported
source and documentation files, validating their repository-relative path
headers, and applying explicitly approved corrections. The implementation is
structured so language rules, scanning, updates, CLI interaction, configuration,
logging, and presentation can be understood and extended independently.

### ✨ Features

#### Scanning and path-header management

- Added recursive discovery and validation of path headers across selected repository targets.
- Added language-aware insertion and replacement of missing or stale headers.
- Added support for Python, JavaScript and TypeScript, Shell, PHP, HTML, and Markdown header syntax.
- Added configurable ignore rules for repositories, virtual environments, caches, build outputs, and user-selected paths.
- Added deterministic repository-relative path rendering with safe handling of existing special lines and trailing newlines.
- Added preview results that distinguish valid, inserted, updated, unsupported, skipped, and failed files.
- Added explicit `--apply` mutation control while keeping scans non-mutating by default.

#### CLI, initialization, and configuration

- Added the `path-header-scanner init` and `path-header-scanner scan <target>` command workflows.
- Added Rich banners, help, panels, progress displays, summaries, and actionable error presentation.
- Added working-directory, apply, dry-run, debug, logging, banner, version, help, and completion controls.
- Added `.config/path_header_scanner/config.toml` with packaged defaults and CLI → configuration → internal-default precedence.
- Added initialization builders, models, registries, presenters, and scaffold generation for project configuration.
- Added rotating file logging alongside configurable console diagnostics.

#### Safety and dry-run behavior

- Made scan preview the default so target files are not changed without `--apply`.
- Added `--dry-run` to initialization and scanning workflows.
- Made scan dry-run override both CLI `--apply` and configured `apply = true` settings.
- Prevented dry-run initialization from creating directories, writing files, overwriting content, or prompting for confirmation.
- Kept read-only discovery, validation, and rendering available during simulation while preventing target-project mutations.
- Added explicit terminal messages describing whether a scan is a preview, dry run, or live apply operation.

- Separated Typer command parsing, options, models, resolution, and presentation under `app/cli`.

- Isolated language-specific header behavior behind focused strategy implementations under `app/languages`.
- Added shared result models, domain exceptions, path utilities, logging utilities, UI components, and theme definitions.
- Separated initialization planning from scaffold persistence so dry-run can stop before the mutation boundary.
- Added an `AGENTS.md` engineering contract covering scan safety, dry-run behavior, configuration, testing, and release safeguards.

### ⚠️ First-release notes

- This is the first formal production release line; there is no previous supported release to migrate from.
- Python 3.11 or newer is supported by the package, with Python 3.14 used for the standard development and container runtime.
- Scans are previews by default; users must opt in with `--apply` to update files.
- `--dry-run` always prevents project-file mutations, including when apply mode is configured.
- Configuration lives at `.config/path_header_scanner/config.toml`.
